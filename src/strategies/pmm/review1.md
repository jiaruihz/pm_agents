## 原始审阅

 我们的做市算法的思路怎么样，作为散户可能在polymarket上赚钱吗？：一句话版

  每秒钟做一次循环：看行情 → 算出该挂什么价 → 跟上次不一样就改单 → 等下一秒。

  ---
  整个流程拆成 6 步

  想象你是一个摊贩，在市场里同时挂"我要买"和"我要卖"两个牌子：

  每秒循环：
  ┌─────────────────────────────────────────────────┐
  │ 1. 拿数据                                        │
  │    查余额、查现有挂单、查持仓、查订单簿             │
  │                                                   │
  │ 2. 算信号                                        │
  │    库存偏了多少？波动率多大？价差该多宽？           │
  │                                                   │
  │ 3. 算价格                                        │
  │    买入价 = 中间价 - 半个价差 - 库存偏移           │
  │    卖出价 = 中间价 + 半个价差 - 库存偏移  ← 这里有bug │
  │                                                   │
  │ 4. 贴近市场                                      │
  │    别人的买一卖一在哪？我挂的价格不能离他们太远      │
  │                                                   │
  │ 5. 算数量                                        │
  │    买多少？卖多少？钱够吗？仓位超限了吗？           │
  │                                                   │
  │ 6. 下单/改单                                     │
  │    跟上次挂的不一样？取消旧的，挂新的               │
  └─────────────────────────────────────────────────┘

  ---
  6 个模块，各管一件事

  ┌────────┬──────────────────────────────┬────────────────────────────────────┬────────────────────────────┐
  │  模块  │             文件             │              干什么的              │          打个比方          │
  ├────────┼──────────────────────────────┼────────────────────────────────────┼────────────────────────────┤
  │ 信号   │ core/signals.py              │ 算库存偏移量、波动率、该多宽的价差 │ 你摊位上的"仪表盘"         │
  ├────────┼──────────────────────────────┼────────────────────────────────────┼────────────────────────────┤
  │ 定价   │ core/pricing.py              │ 算出买入价和卖出价                 │ 你写的"标价牌"             │
  ├────────┼──────────────────────────────┼────────────────────────────────────┼────────────────────────────┤
  │ 锚定   │ core/anchoring.py            │ 把标价往市场实际价格上靠           │ 看隔壁摊位定价，微调自己的 │
  ├────────┼──────────────────────────────┼────────────────────────────────────┼────────────────────────────┤
  │ 下单量 │ core/sizing.py               │ 算每笔挂多少                       │ "这一单我最多出多少钱"     │
  ├────────┼──────────────────────────────┼────────────────────────────────────┼────────────────────────────┤
  │ 策略   │ strategies/multi_level_v1.py │ 把上面 4 个串起来，支持多层挂单    │ 总指挥                     │
  ├────────┼──────────────────────────────┼────────────────────────────────────┼────────────────────────────┤
  │ 引擎   │ engine/tick_engine.py        │ 每秒循环、下单、改单、合并仓位     │ 你的手脚，执行一切         │
  └────────┴──────────────────────────────┴────────────────────────────────────┴────────────────────────────┘

  另外还有两个辅助模块：
  - 风控 risk/circuit_breaker.py：价格暴跌就停机（目前只有"价格跳 10% 就永久关机"这一招）
  - 回测 backtest/：用历史数据跑模拟

  ---
  我们现在做得好的

  1. 代码结构最清晰 — 6 个模块各管各的，比开源项目（poly-maker 全局变量满天飞、kalshi 单文件 400 行）好很多
  2. 下单量衰减做对了 — 持仓多了，加仓方向的量自动缩小，减仓方向不变（pricing.py:48-51）
  3. 库存信号用 sigmoid — 不是简单的线性，仓位越接近极限信号越强，比线性好
  4. 有多层挂单 — multi_level_v1 支持挂几个价位
  5. 有 OFI（买卖压力检测） — 能感知市场一边倒的压力，暂时停掉那边的挂单
  6. 有回测框架 — 能用历史数据验证策略

  ---
  需要发力的 4 块（按严重程度排）

  第 1 块：定价逻辑有 bug — "两边一起挪"的问题

  现在的问题：pricing.py 第 62-63 行

  买入价 = 中间价 - 半个价差 - 库存偏移
  卖出价 = 中间价 + 半个价差 - 库存偏移   ← 买入价和卖出价往同一个方向挪了

  举个例子：你手里已经持了很多 YES（多头），你想少买、多卖来减仓：
  - 买入价往下挪 ✅ — 离市场价更远，不容易买到更多
  - 卖出价也往下挪 ❌ — 离市场价更远，更难卖出去，减仓反而更慢了！

  正确做法：只挪加仓那一边。持多头就只把买入价推远，卖出价保持不动，让减仓更容易成交。

  这是开源项目 prediction-market-maker 用版本历史证明的：v01 对称偏移亏钱（-$17），v10 改成非对称后直接翻正（+$4）。一行改错，从亏到赚。

  ---
  第 2 块：波动率高的时候只知道"加宽价差"，不知道"不挂单"

  现在：signals.py 的 required_spread() 在波动率高时线性加宽价差，但继续挂单。

  问题：市场价格跳 20 分的时候，你加宽到 5 分价差根本没用——别人看到你的单子就知道有流动性可以打，你成了"被收割的锚"。

  正确做法（开源项目 poly-maker 实战验证）：波动率超阈值 → 全部撤单，暂停交易 30 分钟到几小时，等市场平静了再回来。

  我们的熔断器只有"净值跌 10% 永久关机"这一招，太粗暴了。需要一个中间档：波动率超标 → 暂停 → 冷却后重新评估。

  ---
  第 3 块：不看订单簿深度

  现在：anchoring.py 只看"买一价"和"卖一价"来锚定自己的报价。

  问题：Polymarket 上经常有"幽灵单"——买一只有 $5，后面 $100 的厚单在第二三档。你跟着 $5 那个价挂，你的单子会被后面的厚单瞬间吃掉（被逆向选择）。

  正确做法（poly-maker 的做法）：跳过深度不够的价位，找到真正有厚度的档位再锚定。

  ---
  第 4 块：挂单不算敞口

  现在：sizing.py 的 target_sizes() 只看当前持仓和余额来算下单量，完全不管你还有多少挂单在排队。

  问题：你持仓 0，但挂了 3 个买单每个 $100，实际风险敞口是 $300。如果全部成交，你瞬间变成 $300 多头，但系统以为你还是 0 仓位。

  好消息：pricing.py 里 open_buy_qty / open_sell_qty 参数已经传进来了，tick_engine.py 里也已经算好了。但 sizing.py 没用它们——管道已经铺到门口了，就差接上。

  ---
  总结成一张图

             做得好 ✅                    做得不好 ❌
    ┌─────────────────────┐    ┌──────────────────────────┐
    │ 代码结构清晰          │    │ 定价：双边一起挪（bug）    │
    │ 下单量衰减方向正确     │    │ 波动率高还在挂单          │
    │ sigmoid 库存信号      │    │ 不看订单簿深度            │
    │ 多层挂单              │    │ 挂单敞口没算进仓位        │
    │ OFI 买卖压力检测      │    │ 熔断器太粗暴              │
    │ 回测框架              │    │ 没有奖励位置优化          │
    └─────────────────────┘    └──────────────────────────┘

  最关键的是第 1 块——定价 bug 是"从亏变赚"的开关，改 pricing.py 大约 10 行代码就能修。第 2 块加上之后，高波动时不用再怕被收割。3 和 4 是进一步优化，让策略更稳。
