## 第一部分：今天的完整收获

### 1. 旧打法（A/B/C）为什么全部失败 —— 不是执行问题，是结构问题

过去一个月跑的三个策略家族，全部返回干净的 null：

| 家族 | 假设 | 结局 |
|---|---|---|
| **A = H_A** | 自家天气模型能比市场更准地识别错价档位 | 已证伪：模型 Brier 在干净样本外输市场 16–30% |
| **B = H_B** | 市场有结构性 favorite-longshot 偏差，fade 它/买 NO 能结构性收割 | 测了，没有可交易的净 edge |
| **C = H_C** | 不求全局，筛一个 GFS 表现好的城市子池 | 测了，子池不能前瞻稳定（5月明星城6月翻车） |

**关键认知：A/B/C 不是"天气的三个方向"，而是同一种打法的三个变种**，它们共享三根从没被撬动的柱子：

- **柱子①（时间）**：所有信号都在 T-22~28h（提前约一天）。
- **柱子②（用预测不用观测）**：永远喂 forecast 模型预测当天最高温，从不用"当天已观测到的温度"。
- **柱子③（价格当 level）**：edge = model_p − market_price 一个快照，从不看价格路径。

A/B/C 全部死在**柱子①+②**：用提前一天的预报去赌具体落在哪一档。

### 2. 为什么"提前一天靠预报"在物理上必死（带数字）

deep-research 查到的同行评审证据（AMS / Baars & Mass 等）：

| 事实 | 数字 | 出处 |
|---|---|---|
| 提前 24h 单站日最高温预报 MAE | **≈ 1.1°C（2.0–2.6°F）** | NWS 2.04°F / consensus-MOS 2.10°F |
| 市场档宽 | **1°C 一档**（已确认是摄氏度） | 用户确认 |
| 最常见的绝对误差 | **正好 1°F** | Baars & Mass Fig 3 |
| 多天预报命中正确档比例 | 低到 **25–28%**（还是 5°F 宽档） | Brooks/Witt/Eilts OKC |
| 冬季/剧烈变温日 MAE | 飙到 **4.4–5.2°F** | OKC Table 2 |
| AI 模型（GraphCast/AIFS）能救吗 | T2m 短期 RMSE 改善 >15%，但只在平坦地形+正午+冬季高压，且是网格非单站；**压不到亚度级** | WeatherBench2 / ECMWF AIFS blog |

**结论（物理盖棺）**：day-1 预报 MAE（1.1°C）≥ 档宽（1°C）。**提前一天，预报的平均误差就超过一整档。这不是模型烂，是大气可预测性的物理极限，换最好的 AI 模型也跨不过。** 所以 forecast-only（含 A/B/C）物理上注定跨多档模糊，死得不冤。

### 3. 为什么"靠预测"这件事在预测市场里本来就不计分

另一份 deep-research（222M 笔 Polymarket 交易，Della Vedova 2026）：

- **预测准不准，跟盈亏基本无关**：预测能力强的人反而是负收益（到得晚、买在差价上）；决定盈亏的是**执行**（2.52 美分执行差），预测技能与盈利相关性仅 ρ≈0.13。
- 散户挑对边 51.3% 照样亏；机器人挑对边 49.9% 赚了 1.34 亿。**差别不在知道什么，在何时交易。**
- 天气盘是死角：占全平台体量极小（体育/政治/加密占 90%）；唯一用专有模型做天气盘的专业公司（Jua）自己说"流动性太低，养不起像样基金"。
- 真正赚钱的人靠：**速度**（latency arb，bot，你抢不了）、**承担风险收溢价**（天气衍生品，是另一种生意）、或**操纵结算源**（巴黎传感器案，犯罪）。

**结论**：在这个生态里"靠预测找错价"结构性不可行。但这条结论**只杀"靠预测"，不杀"靠已发生的事实抢先反应"**——这是 M3 的入口。

### 4. 转机：唯一物理上站得住的方向

deep-research 总结原话：**"对结算市场而言，决定性的杠杆不是更好的预报，而是用'已观测到的当日最高温'做临近时段的条件化。一旦日内峰值过去，残余不确定性会塌缩到远低于预报 MAE。"**

而且查证发现：**这个"峰值后残差分布"全世界没人公开量化过**——这是一个学术空白，而你手里恰好有历史 METAR 能填它。

### 5. 关键的规则事实（决定 M3 时间窗存不存在）

仓库文档已记载 weather 合约有 4 个时间基准：

- **结算 T = 当地时间 22:00**
- 报告 T = 次日早 6AM
- 模型 T = GFS UTC 00/06/12/18
- 市场 T = endDate

**含义**：当天物理最高温通常在**下午 2–4 点**出现，而结算锚在**当地 22:00**。所以**傍晚到晚间存在一个可交易窗口**：峰值已成事实，但市场还能交易。M3 的时间窗**真实存在**——"晚上才下判断"不是缺陷，是这个策略的核心特性。

## 第二部分：新策略思路（M3 —— 傍晚已观测锁定 + 二次升温过滤）

### 6. 一句话定义

> **不预测明天，只在傍晚交易"今天白天已经基本锁定结果"的 city-day。** 用当地傍晚已观测到的当日最高温作为硬下界，过滤掉有晚间二次升温风险的日子，在剩下的高确定性 city-day 上，吃市场仍锚定在早盘预报、没跟上已观测现实的价差。

### 7. 为什么它能绕过那三道物理墙

| 墙 | forecast-only 怎么死 | M3 怎么绕过 |
|---|---|---|
| 预报误差 ≥ 档宽 | 提前一天 1.1°C 误差，分不清相邻档 | **不预测整天，只看已观测 max（事实）+ 残余几小时** → 误差大幅塌缩 |
| 预测不计分 | 靠预测的人到得晚、买差价 | **靠抢先反应已发生事实**，不是预测；傍晚读 METAR 可能是最早反应已观测现实的人之一 |
| 价格陈旧难判断 | 不知道公允价该是多少 | **已观测 max 给出近确定的公允价**，与市场早盘锚定价的差就是 edge |

**它本质是两层结构，两层都不需要 1°C 级别的预测精度：**
- **第一层（信息塌缩）**：已观测 max 是最终 max 的硬下界——确定性信息，不是预测。
- **第二层（风险过滤）**：判断"今晚会不会被二次升温改写"——一个**粗粒度二元判断**（反弹/不反弹），比精确点预测容易一个数量级。

### 8. 核心机制：硬下界 + 残余塌缩

在当地傍晚某时点（如 19:00–20:00）：
- 当天已观测最高温 = `O`
- 最终结算最高温 `M ≥ O`（已观测是硬下界，物理铁律）
- 残余风险只剩：**22:00 前还会不会有时段把温度顶过当前峰值？**

如果当天峰值已过、在稳定降温、且无晚间升温信号 → `M ≈ O`，结果几乎锁定在 O 所在档。此时若市场还把概率摊在好几档（锚早盘预报）→ 你下注 O 所在档（或 BUY_NO 那些已不可能的更高档）。

### 9. 二次升温过滤（这是成败关键，必须事前可判定）

**铁律：过滤必须用"下注那一刻就能看到的信息"，不能事后诸葛。**

可下注（低反弹风险）的事前信号：
- 已观测峰值明确已过，温度进入稳定下降通道
- 晴朗、辐射降温为主，无云量突增（云会保温托底）
- 无暖平流/暖锋逼近、无焚风、无强夜间南风信号

Pass（高反弹风险，不碰）：
- 暖锋/暖平流逼近
- 焚风、强南风（夜间可能回暖）
- 云量突增（夜间保温，温度不跌甚至回升）
- 海洋性/温带气候中已知的晚间二次升温城市

> 注意：这一层**仍然会用到 forecast/气象条件**，但用法和被证伪的 A/B/C 完全不同——A/B/C 用预报去**精确预测几度**（1.1°C 误差，做不到）；M3 只用气象条件判断一个**二元粗粒度问题**"会不会反弹"，这容易得多，不撞物理墙。

### 10. 结构性优势：这是筛选问题，不是预测问题

- 你**不需要对所有城市有 edge**，只需要能**识别出哪些 city-day 已锁定**。
- 你**不被迫每天下注**——确定性不够的全部 pass，只在干净牌上出手。
- 把"预测问题"降级成"筛选问题"——筛选比预测容易得多，且容错高。

### 11. 它相对其他参与者的真实优势在哪

- **不是更好的模型**（模型证明赢不了市场）。
- **不是更快的速度**（拼不过 bot）。
- **是别人没做的功课**：对"哪些 city-day 在傍晚已经物理锁定、且无晚间反弹风险"做了系统性的历史量化。散户看早盘预报、bot 扎堆政治/加密、专业气象公司嫌盘子小——**这个又小又烦、需要 METAR + 物理 + 历史残差功课的角落，可能真没人在做。**

## 第三部分：怎么验证 M3 是真金还是又一个 null

### 12. 两个决定生死的数字（你的数据能测，外部世界没量化过）

**数字一 —— 塌缩有多干净（决定"有没有可锁定的城市"）**
> 对每个城市、每个历史日，重建"当地傍晚 19:00/20:00 时的已观测 max"，对比"最终当日 max"，算残差分布。按城市/季节切。
> - 残差 P90/P95 **<< 1°C** 的城市 → 物理上可锁定 → 进候选池。
> - 残差 ≥ 1°C 的城市 → 排除。

**数字二 —— 过滤有多有效（决定"坏 case 能不能事前躲掉"）**
> 在"残差大（被晚间反弹改写）"的 case 里，有多少是事前用气象条件/温度路径能识别并 pass 掉的？
> - 坏 case 大多有事前征兆（暖锋/风向/云量/降温斜率）→ 过滤有效，剩余池干净 → M3 成立。
> - 反弹经常无征兆突袭 → 过滤失效，有尾部风险 → M3 打折或死。

### 13. 验证纪律（避免重蹈 A/B/C 的过拟合覆辙）

任何"这个城市可做"的结论必须过三门，否则只能标 inconclusive：
1. **前瞻门**：train 窗选城市/规则 → 冻结 → holdout 窗复核同号且仍成立（防"5月明星城6月翻车"）。
2. **基准门**：超额于"傍晚无脑买已锁定档/买已不可能档的 NO"这个零模型。
3. **显著性门**：cluster bootstrap（按 city-day 聚簇）95% CI 不跨 0，有效样本 n_eff≥30。

并必须扣真实点差（best_ask，非 mid）、过 CLOB fill coverage gate。

### 14. 落地步骤（第一步不碰交易，只算物理残差）

1. **补数据**：当前"逐时刻已观测温度"覆盖率仅 0.9–4%（roadmap M3，未建）。先补"重建每个时点已观测 running max"的采集/回填。
2. **测数字一**：跑塌缩残差脚本 → 得到候选城市池。
3. **测数字二**：跑过滤有效性脚本 → 验证坏 case 可事前识别。
4. **若 1+2 通过**：在候选池 + 过滤规则上，用历史 snapshot 价格做前瞻回测（三门）。
5. **若回测通过**：小额 shadow/live，冻结预注册规则，只前瞻评估。

### 15. 诚实的 kill 条件（什么时候认它也是 null）

- 数字一：主要城市傍晚残差 ≈ 预报 MAE（晚间反弹普遍）→ 塌缩不成立，M3 死。
- 数字二：坏 case 无事前征兆 → 过滤失效，留尾部风险。
- 回测：扣点差后 gap 秒被市场/bot 关闭 → 没有可成交 edge。
- 任一成立 → 干净认 null，这次是用物理数据下的判决，不是回测玄学。
