## 1. 项目定位与总体流程

这是一个 **Polymarket 只读研究/审计管线**，通过公开 API 拉取市场/事件（Gamma）与行情/订单簿（CLOB），落地 SQLite（结构兼容未来迁移至 PG 的设计），可选使用 LLM 抽取规则结构，最终计算流动性/摩擦/规则评分并产出候选列表，供人工复核。

核心流程（CLI 典型顺序）：

1) init-db：初始化数据库
2) sync：同步 Gamma 市场/事件（raw + canonical）
3) enrich：同步 CLOB 价格/订单簿
4) parse：可选 LLM 规则抽取
5) candidates：评分 + 过滤候选导出

## 3. 入口与命令

入口脚本在 `pyproject.toml` 中注册：

- `pmr = research.cli:app`

CLI 命令概览：

- `pmr init-db`
  - 初始化 SQLite 表结构。
- `pmr sync --active true --pages 5 --page-size 100`
  - 拉取 Gamma markets + events，写入 raw 与 canonical。
- `pmr enrich --prices --orderbooks --limit 500 --top-n 20`
  - 拉取价格与订单簿 Top-N。
- `pmr parse --llm --batch 100`
  - LLM 规则抽取（如未配置 LLM 则跳过）。
- `pmr candidates --min-volume 20000 --max-spread 0.06 --output output/candidates.csv`
  - 评分并导出候选。
- `pmr pap-run`
  - 运行 PAP 状态机（同步 → 过滤 → 解析 → 调查 → 筛选 → 产出）。

## 3.1 PAP 状态机与节点

状态枚举：

- NEW
- IGNORED
- READY_TO_PARSE
- PARSED
- READY_TO_SEARCH
- INVESTIGATED
- READY_FOR_DECISION

节点职责：

- `nodes/ingestor.py`
  - 同步 Gamma + 复活 IGNORED -> NEW。
- `nodes/filter.py`
  - 流动性/分类/价格粗筛，NEW -> IGNORED 或 READY_TO_PARSE。
- `nodes/parser.py`
- LLM 解析，写入 market_rule_parses，分流 READY_TO_SEARCH / PARSED。
- `nodes/investigator.py`
  - 证据采集（当前为占位 stub），READY_TO_SEARCH -> INVESTIGATED。
- `nodes/quant.py`
  - 计算 edge 并筛选候选。
- `nodes/builder.py`
  - 生成 markdown 报告并标记 READY_FOR_DECISION。

## 5. 数据模型与持久化

`src/strategies/rule_lawyer/schema.py` 定义表：

- `markets_raw`：Gamma 原始市场 JSON
- `events_raw`：Gamma 原始事件 JSON
- `events`：规范化事件表（含 tags 分类）
- `markets`：规范化市场主表（包含 status/status_updated_at）
- `prices`：token 价格/中间价
- `orderbook_levels`：Top-N 订单簿级别
- `market_rule_parses`：LLM 规则解析结果
- `evidence_locker`：调查证据存档
- `scores`：评分结果

说明：

- `markets` 不存 `last_trade_price`，价格/盘口请从 `prices`/`orderbook_levels` 查询。
- `market_rule_parses` 新增 `rule_score` 与 `rule_score_components_json`，用于可解释的规则分。
- `markets` 额外存 `event_*` 字段（`event_ids_json/event_slugs_json/event_titles_json/event_tickers_json`），用于关联上游事件分类。

`src/strategies/rule_lawyer/db.py` 提供：

- `get_connection()`：开启 SQLite（WAL 模式）
- `init_db()`：执行 `CREATE_TABLES_SQL`
- `upsert_many()`：基于 UPSERT SQL 批量写入

`src/strategies/rule_lawyer/storage.py` 提供：

- `save_*()`：统一 upsert 到各表
- `get_*()`：关键读取
  - `get_active_token_ids()`
  - `get_markets_for_parsing()`
  - `get_markets_with_tokens()`
  - `get_latest_price()`
  - `get_latest_orderbook()`
  - `get_market_rule_parse()` / `get_market_rule_parse_samples()`

## 6. Gamma 数据同步

`src/strategies/rule_lawyer/clients/gamma.py`：

- `fetch_paginated()`
  - Gamma API 的 offset/limit 分页方式，直到无数据或到达 page 上限。
- `normalize_market()`
  - 统一字段：`market_id/slug/question/description/rules/category/active/resolved/end_at_utc/volume/liquidity/outcomes_json/outcome_prices_json/clob_token_ids_json` 等。
  - UTC 时间转换。
- `fetch_markets()`、`fetch_events()`
  - 入口封装。

`src/strategies/rule_lawyer/pipeline.py` 中 `sync_gamma()`：

- 拉取 markets/events → `save_markets_raw`/`save_events_raw`
- 规范化后写入 `markets`

## 7. CLOB 行情与订单簿

`src/strategies/rule_lawyer/clients/clob.py`：

- `fetch_price_and_book(token_id, top_n, archive_books)`
  - 拉 `/midprice`, `/price`, `/book`
  - 计算 mid/bid/ask、spread、spread_pct_mid
  - 订单簿仅存 Top-N 层
  - 可选 gzip 归档完整 book
- `enrich_token_batch()`
  - 并发拉取多个 token

`src/strategies/rule_lawyer/pipeline.py` 的 `enrich_prices_orderbooks()`：

- 读取 active token IDs
- `clob_client.enrich_token_batch()` 并写入 prices / orderbook_levels

## 8. HTTP 客户端能力

`src/strategies/rule_lawyer/clients/http.py` 关键机制：

## 10. 指标计算与评分

`src/strategies/rule_lawyer/metrics.py`：

- 计算 spread / spread_pct_mid
- 深度：1%/2% bid/ask depth

`src/strategies/rule_lawyer/scoring.py`：

- `liquidity_score()`
  - volume / depth / spread 的组合
- `friction_score()`
  - liquidity + spread 组合
- `rule_score()`
  - clarity + dispute_risk + trigger_type bonus
- `total_score()`
  - 基于权重 `w_rule / w_friction`

## 11. 候选生成

`src/strategies/rule_lawyer/pipeline.py`：

- `compute_scores_and_candidates()`
  - 读取 markets + price + orderbook + market_rule_parses
  - 计算 metrics + scores
  - 过滤条件：active/未解决/volume/ spread/ clarity/ dispute_risk
  - 输出候选 + 保存 scores
